# Cross-repo documentation/folder standard

## Problem

Across the six actively-worked repos under `~/REPO/ME` (roset.sh, iklo,
what-about, guiltty, obsidian-hivemind, wawk.js), there is no consistent
answer to "where does the agent doc live," "where do specs live," "where do
tasks live," or "does this repo even have an agent doc." Evidence gathered
2026-07-31/08-01:

| | roset.sh | iklo | what-about | guiltty | obsidian-hivemind | wawk.js |
|---|---|---|---|---|---|---|
| Agent doc | AGENTS.md | AGENTS.md | AGENTS.md | none | none | none |
| `repo.toml` | ✓ | — | ✓ | ✓ | — | ✓ |
| `tasks/` dir | — (added 2026-08-01) | (specs/NNN/tasks.md) | ✓ | ✓ | ✓ | — |
| Spec location | `SPEC.md` | `specs/NNN-slug/` | `docs/specs/` | `docs/spec.md` | — | — |

Half these repos have no agent doc at all; no two agree on where specs or
tasks live. This is a genuinely new standard to define, not a restore.

## Decision

### 1. `repo.toml` gets a `stage` field

```toml
stage = "prototype"  # prototype | in-progress | released | archived
```

- **`prototype`** — exploring the idea, API/schema still churning, may be
  abandoned.
- **`in-progress`** — committed direction, active development, real design
  decisions being made.
- **`released`** — has actual users/consumers (even just "you, depending on
  it from another repo"), stability matters.
- **`archived`** — no longer maintained, kept for reference only.

`repo.toml` remains Claude-generated by convention (not tool-generated); the
`repo-standard` skill (below) is what actually writes/checks it going
forward.

### 2. Each stage maps to a doc/folder tier

The PR-process layer (worktrees, dedicated `owkwo-bot` git identity sourced
from Doppler, issue → `tasks/issue-N-*.md` → PR, per the
`pull-request-process`/`map-issue-to-tasks`/`fix-mapped-issue` skills)
applies uniformly across every non-archived stage — that's *how work ships*,
not a documentation tier. The tiers below are about *what documentation and
ceremony exists*, which does scale with stage.

| Artifact | `prototype` | `in-progress` (= iklo today) | `released` | `archived` |
|---|---|---|---|---|
| `repo.toml` (`stage=...`) | ✓ | ✓ | ✓ | ✓ |
| `AGENTS.md` | terse (rules/setup/validation, roset.sh's current style) | rich (reality-check of what's implemented, decided rules, dev commands, "where things live" map) | in-progress + versioning/migration discipline | untouched, not enforced |
| `README.md` | full outward-facing (status, limitations, next steps) | short — AGENTS.md is the hub, README just orients | polished for external consumers (install, badges, supported versions) | frozen, marked archived |
| Spec | single `SPEC.md` | `specs/NNN-slug/{spec,plan,tasks}.md` (spec-kit) | same as in-progress | none required |
| ADRs | none | `specs/decisions/ADR-NNNN` | same | none |
| Governing principles | none | `.specify/memory/constitution.md` (full spec-kit scaffolding, not a lookalike) | same | none |
| `tasks/issue-N-*.md` | created on demand per issue | same, coexists with `specs/NNN` for planned feature work | same | none |
| Extras | — | project reference doc if useful (iklo's `LANGUAGE.md`) | `CHANGELOG.md`, maybe `SECURITY.md` (obsidian-hivemind precedent) | — |

"In-progress" means adopting iklo's actual `.specify/` spec-kit machinery
wholesale (templates, scripts, `/speckit.*` slash commands included), not a
hand-rolled imitation of its folder names.

### 3. Enforcement: on-demand `repo-standard` skill

A new skill in this repo (`rsenna-claude-plugins`), alongside
`pull-request-process` / `map-issue-to-tasks` / `fix-mapped-issue`:

- **`audit`** — read `repo.toml`'s `stage`, diff the repo's actual
  files/folders against that stage's required tier, report what's
  missing/misplaced. Read-only, no side effects.
- **`scaffold`** — same diff, but offers to create what's missing. Never
  overwrites existing content (same non-destructive posture as
  `map-issue-to-tasks`).

Triggered on demand only (`/repo-standard audit`, `/repo-standard scaffold`)
— explicitly **not** wired into `pull-request-process` as an automatic
pre-PR check. Doc/folder shape is advisory/structural, not correctness, so a
human-in-the-loop nudge fits better than a hard gate that could block
unrelated work.

## Non-goals

- No git hook or CI enforcement of this standard (see above).
- No retroactive rewrite of iklo's already-working `.specify/` setup — it's
  the reference implementation for `in-progress`, not something to change to
  fit a new abstraction.
- No requirement that every repo immediately jump to its "correct" tier —
  this spec defines the target shape; migration happens per-repo, on demand,
  via the `repo-standard` skill once it exists.

## Open follow-ups (not blocking this spec)

- Implement the `repo-standard` skill itself (audit + scaffold).
- Decide `stage` for each of the 6 repos and write/update their `repo.toml`.
- Roll AGENTS.md/README/folder changes out per repo, per its tier, each
  through the normal issue → worktree → PR flow — not a single mass edit.
